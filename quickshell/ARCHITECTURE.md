# Architecture

A high-level map of how this Quickshell config is organized. If you only read one
doc to get oriented, read this one.

## Directory map

```
shell.qml          Entry point. Opens one panelBar + panelBorder + panelPopout
                   per screen. panelPopout hosts PopoutItem children with
                   HyprlandFocusGrab for click-outside-to-close.
                   Sets pragmas (Singleton, ComponentBehavior) and `settings.watchFiles`
                   for hot-reload.

modules/           Top-level surfaces. Each subdirectory owns one surface and
                   its widgets/qmldir. Today only `bar/` exists; future Tier 3
                   work (lock, notif, osd) will land here as siblings.

  modules/bar/     Bar widgets — the things visibly placed in the bar.
                   Each module extends ModuleWrapper (click + scroll + tooltip).
                   Layouts is the Row container (Left/Center/Right).

popouts/           Popup contents, decoupled from the modules that trigger them.
                   Each popout is a plain Item placed inside a PopoutItem in
                   shell.qml. They open/close via the Visibilities singleton.

services/          Global Singletons holding shared state.
                   Theme         — color/font palette (regenerated by matugen
                                   on wallpaper change — gitignored)
                   Visibilities  — which popout is currently open
                   CpuUsage      — CPU% / cores / load average / Tctl temp from /proc + hwmon
                   RamUsage      — RAM and swap from /proc/meminfo
                   GpuUsage      — GPU% / VRAM / temps from /sys/class/drm/card1/device + hwmon
                   NetworkSpeed  — Rx/Tx rate aggregation
                   Players       — MPRIS player tracking (Tidal et al.)
                   Tick          — shared 1 Hz heartbeat for pollers

components/        Reusable visual / interactive primitives, no business logic.
                   StyledText, IconButton, PopoutItem, Tooltip, SectionHeader,
                   KeyValueRow, ProgressBar, Sparkline, ExclusionZone.
                   Depend only on services/ (Theme) — never on modules/.
```

## How things connect

```
shell.qml
  ├── panelBar         (PanelWindow Top, 40px) — bar interactive
  │     └── modules/bar/Audio.qml   (extends ModuleWrapper, id: audioModule)
  │           ├── reads:  Pipewire service, Theme
  │           ├── coords: services/Visibilities (which popup is shown)
  │           └── onClicked: Visibilities.toggle("audio")
  │
  ├── panelPopout      (PanelWindow Top, fullscreen, ExclusionMode.Ignore)
  │     ├── mask: Region { bar 40px + dynamic sub-region for visible popout }
  │     ├── HyprlandFocusGrab { windows: [panelPopout.QsWindow.window];
  │     │                        active: Visibilities.current !== "";
  │     │                        onCleared: Visibilities.close() }
  │     └── PopoutItem { id: audioPopout; wrapper: audioModule; name: "audio" }
  │           └── AudioPopup { anchors.centerIn: parent }
  │
  └── panelBorder      (PanelWindow Bottom, fullscreen) — decorative border
```

Three rules keep this navigable:

1. **A module never reads another module.** Cross-module state lives in `services/`.
2. **A popout never reads its triggering module.** It pulls everything it needs
   from `services/` or from properties passed by the wrapping `PopoutItem`.
3. **Only one popout is open at a time.** `Visibilities.current` is the single
   source of truth; modules toggle via `Visibilities.toggle("name")`.

## PopoutItem positioning model

`PopoutItem` lives inside `panelPopout` (a different `QsWindow` than `panelBar`
where its wrapper module lives). Qt's `mapToItem`/`mapToScene` do **not** bridge
cross-window — scene graphs are separate. The component computes its position via:

```qml
const g = wrapper.mapToGlobal(localX, 0);            // absolute screen coords
const p = panelWindow.contentItem.mapFromGlobal(g.x, g.y);
```

`mapToGlobal`/`mapFromGlobal` are instance methods on `Item` (Qt 5.15+) that work
in absolute screen space, so they're scene-graph independent.

## Recipes

### Add a new module to the bar

1. Create `modules/bar/Foo.qml` extending `ModuleWrapper`.
2. Add the line `Foo 1.0 Foo.qml` to `modules/bar/qmldir`.
3. Place it in `Layouts.qml` (or whichever layout file holds the row).

### Add a popup to an existing module

1. Create `popouts/FooPopup.qml` as a plain `Item { anchors.fill: parent; … }`.
2. Add `FooPopup 1.0 FooPopup.qml` to `popouts/qmldir`.
3. In the bar module (`modules/bar/Foo.qml`), give it an id and a click handler:
   ```qml
   // modules/bar/Foo.qml
   ModuleWrapper {
       id: fooModule  // ← needed so the PopoutItem can reference it as wrapper
       // ... content ...
       onClicked: Visibilities.toggle("foo")
   }
   ```
4. In `shell.qml`, inside `panelPopout`, add a `PopoutItem`:
   ```qml
   PopoutItem {
       id: fooPopout
       panelWindow: panelPopout
       wrapper: fooModule
       name: "foo"
       alignment: "center"   // "left" | "center" | "right"
       implicitWidth: 320
       implicitHeight: 200

       FooPopup { anchors.centerIn: parent }
   }
   ```
5. Extend the `mask: Region` of `panelPopout` to include the popout zone:
   ```qml
   Region {
       x: fooPopout.x
       y: fooPopout.y
       width: fooPopout.visible ? fooPopout.implicitWidth : 0
       height: fooPopout.visible ? fooPopout.implicitHeight : 0
   }
   ```
   When the popout is hidden, `width/height = 0` makes the sub-region inert.

### Add a shared service

1. Create `services/Foo.qml` with `pragma Singleton` at the top.
2. Add `singleton Foo 1.0 Foo.qml` to `services/qmldir` (lowercase `singleton`).
3. Anywhere: `import "../services"` then read `Foo.someProperty`.

## Conventions

- **Colors and fonts** go through `Theme.*` tokens — never hardcode a hex.
- **Pipewire bindings are lazy** — wrap any node you read from with a
  `PwObjectTracker { objects: [thatNode] }` or its values come back undefined.
- **Mutating an array in place does not retrigger bindings** — always reassign
  the whole array (`root.list = newArr`, not `root.list.push(...)`).
- **`states` is reserved on `Item`** — don't name a property `states`.
- **Repeater delegates** should declare `required property T modelData` and
  `required property int index` — typed errors beat silent undefined.

## Gotchas worth knowing

- Hot-reload watches QML files but **not** `qmldir` — after editing a `qmldir`
  you usually need to touch a QML file or restart Quickshell.
- `services/Theme.qml` on disk is regenerated by matugen on every wallpaper
  change. The source of truth is `matugen/templates/Theme.qml`. Don't commit
  the regenerated output (it's gitignored).
- Two MouseAreas on top of each other: the one declared *later* wins event
  capture. Use `HoverHandler` if you need hover detection that coexists with
  multiple click zones.
