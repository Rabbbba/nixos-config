# Architecture

A high-level map of how this Quickshell config is organized. If you only read one
doc to get oriented, read this one.

## Directory map

```
shell.qml          Entry point. Uses Variants → Scope to instantiate one bar
                   per matching monitor (currently filtered to AW3423DWF).
                   Each instance gets:
                   - panelBar     (PanelWindow Top, 40px) — interactive bar
                   - panelBorder  (PanelWindow Bottom) — decorative border,
                     click-through via empty mask, drawn via MultiEffect
                     inverted cutout (20px margins, 24px corner radius)
                   - panelPopout  (PanelWindow Top, fullscreen) — popout host
                   - 3× ExclusionZone (left, right, bottom, 20px each)
                   Sets pragmas (UseQApplication, ComponentBehavior: Bound)
                   and `settings.watchFiles` for hot-reload.

modules/           Top-level surfaces. Each subdirectory owns one surface and
                   its widgets/qmldir. Today only `bar/` exists; future Tier 3
                   work (lock, notif, osd) will land here as siblings.

  modules/bar/     Bar widgets — the things visibly placed in the bar.
                   Each module extends ModuleWrapper (click + scroll + tooltip)
                   or is a plain Item for grouped widgets.
                   Layouts is the Row container (Left/Center/Right).
                   Full registry (qmldir):
                     ModuleWrapper, Layouts           — infrastructure
                     Audio, Bluetooth, Clock, Cpu,    — sensor/control modules
                     Gpu, Network, Ram,
                     SystemTray                       — SNI tray (right-click → menu)
                     Tags                             — Hyprland workspace pills
                     Tidal                            — MPRIS "now playing" pill
                     Title                            — active window title

popouts/           Popup contents, decoupled from the modules that trigger them.
                   Each popout is a plain Item placed inside a PopoutItem in
                   shell.qml. They open/close via the Visibilities singleton.
                   Full registry (qmldir):
                     AudioPopup, BluetoothPopup, CalendarPopup, CpuPopup,
                     GpuPopup, PowerPopup, RamPopup, TidalPopup, WifiPopup

services/          Global Singletons holding shared state.
                   Theme         — color/font/animation tokens. Aggregates
                                   ColorTokens (colors) + font/anim definitions.
                   ColorTokens   — regenerated by matugen on wallpaper change
                                   (gitignored). Source of truth:
                                   matugen/templates/ColorTokens.qml.
                   Visibilities  — which popout is currently open
                   CpuUsage      — CPU% / cores / load average from /proc;
                                   Tctl temp via NativeHwmon
                   RamUsage      — RAM and swap from /proc/meminfo
                   GpuUsage      — GPU% / VRAM from /sys/class/drm/card1/device;
                                   temps via NativeHwmon
                   NetworkSpeed  — Rx/Tx throughput via NativeNetwork;
                                   history + formatting in QML
                   Players       — MPRIS player tracking (Tidal), with volume
                                   auto-restore after track changes
                   Tick          — shared 1 Hz heartbeat for pollers
                   History.js    — pure-JS utility: rolling array push with
                                   max length (used by NetworkSpeed, CpuUsage)

components/        Reusable visual / interactive primitives, no business logic.
                   StyledText, IconButton, PopoutItem, Tooltip, SectionHeader,
                   KeyValueRow, ProgressBar, Sparkline, ExclusionZone.
                   Depend only on services/ (Theme) — never on modules/.

plugin/            Native C++ QML module `NativeSensors`, built by a Nix
                   derivation and put on QML_IMPORT_PATH. Reads sysfs directly
                   in C++ instead of spawning a process per tick.
                   NativeSensor   — abstract base class with QTimer-driven
                                    polling; subclasses override poll()
                   NativeHwmon    — hwmon temperatures (CPU/GPU), parametrized
                                    by sensorName / tempIndex / hwmonRoot
                   NativeNetwork  — Rx/Tx throughput from /proc/net/route +
                                    /sys/class/net (no `sh -c` fork per poll)
                   NativeRam      — RAM/swap from /proc/meminfo
                                    (MemTotal, MemAvailable, Buffers, Cached,
                                     SwapTotal, SwapFree)
```

## How things connect

```
shell.qml
  Variants → Scope (one per AW3423DWF monitor)
  │
  ├── panelBar  (PanelWindow Top, 40px)
  │     ├── Row (left-aligned)
  │     │     ├── nixBtn          → toggles "power" popout
  │     │     ├── Tags            → Hyprland workspace pills (ScriptModel)
  │     │     ├── Title           → active window title (per-monitor)
  │     │     └── Layouts         → user-defined left/center/right Row
  │     ├── Clock (centered)      → toggles "calendar" popout
  │     └── Row (right-aligned)
  │           ├── SystemTray      → SNI tray (right-click → menu)
  │           ├── Tidal           → "now playing" pill (MPRIS)
  │           ├── Gpu, Cpu, Ram   → sensor readouts
  │           ├── Bluetooth       → rfkill state poller
  │           ├── Network         → throughput display
  │           └── Audio           → pipewire volume
  │
  ├── panelBorder  (PanelWindow Bottom, fullscreen, ExclusionMode.Ignore)
  │     └── Rectangle + MultiEffect (inverted cutout mask, 20px margin, 24px radius)
  │         mask: Region {}   ← empty → fully click-through
  │
  ├── panelPopout  (PanelWindow Top, fullscreen, ExclusionMode.Ignore,
  │                 WlrKeyboardFocus.OnDemand — needed for WifiPopup TextInput)
  │     ├── mask: Region { sub-Region per visible popout }
  │     ├── HyprlandFocusGrab { windows: [panelPopout.QsWindow.window];
  │     │                        active: Visibilities.current !== "";
  │     │                        onCleared: Visibilities.close() }
  │     └── PopoutItem × 9:
  │           calendarPopout ← clockModule        CalendarPopup
  │           cpuPopout      ← cpuModule          CpuPopup
  │           gpuPopout      ← gpuModule          GpuPopup
  │           ramPopout      ← ramModule          RamPopup
  │           audioPopout    ← audioModule        AudioPopup
  │           networkPopout  ← networkModule      WifiPopup
  │           btPopout       ← btModule           BluetoothPopup
  │           tidalPopout    ← tidalModule        TidalPopup
  │           powerPopout    ← nixBtn             PowerPopup
  │
  └── ExclusionZone × 3  (left 20px, right 20px, bottom 20px)
```

Three rules keep this navigable:

1. **A module never reads another module.** Cross-module state lives in `services/`.
2. **A popout never reads its triggering module.** It pulls everything it needs
   from `services/` or from properties passed by the wrapping `PopoutItem`.
3. **Only one popout is open at a time.** `Visibilities.current` is the single
   source of truth; modules toggle via `Visibilities.toggle("name")`.

## PopoutItem positioning model

`PopoutItem` lives inside `panelPopout` (a different `QsWindow` than `panelBar`
where its wrapper module lives). Qt's `mapToItem`/`mapToScene` do **not** bridge
cross-window — scene graphs are separate. The component computes its position via:

```qml
const g = wrapper.mapToGlobal(localX, 0);            // absolute screen coords
const p = panelWindow.contentItem.mapFromGlobal(g.x, g.y);
```

`mapToGlobal`/`mapFromGlobal` are instance methods on `Item` (Qt 5.15+) that work
in absolute screen space, so they're scene-graph independent.

## Recipes

### Add a new module to the bar

1. Create `modules/bar/Foo.qml` extending `ModuleWrapper`.
2. Add the line `Foo 1.0 Foo.qml` to `modules/bar/qmldir`.
3. Place it in the appropriate Row in `shell.qml` (left, center, or right).
4. If the module needs an id for popout reference, give it one (e.g. `id: fooModule`).

### Add a popup to an existing module

1. Create `popouts/FooPopup.qml` as a plain `Item { anchors.fill: parent; … }`.
2. Add `FooPopup 1.0 FooPopup.qml` to `popouts/qmldir`.
3. In the bar module (`modules/bar/Foo.qml`), give it an id and a click handler:
   ```qml
   // modules/bar/Foo.qml
   ModuleWrapper {
       id: fooModule  // ← needed so the PopoutItem can reference it as wrapper
       // ... content ...
       onClicked: Visibilities.toggle("foo")
   }
   ```
4. In `shell.qml`, inside `panelPopout`, add a `PopoutItem`:
   ```qml
   PopoutItem {
       id: fooPopout
       panelWindow: panelPopout
       wrapper: fooModule
       name: "foo"
       alignment: "center"   // "left" | "center" | "right"
       implicitWidth: 320
       implicitHeight: 200

       FooPopup { anchors.centerIn: parent }
   }
   ```
5. Extend the `mask: Region` of `panelPopout` to include the popout zone:
   ```qml
   Region {
       x: fooPopout.x
       y: fooPopout.y
       width: fooPopout.visible ? fooPopout.implicitWidth : 0
       height: fooPopout.visible ? fooPopout.implicitHeight : 0
   }
   ```
   When the popout is hidden, `width/height = 0` makes the sub-region inert.

### Add a shared service

1. Create `services/Foo.qml` with `pragma Singleton` at the top.
2. Add `singleton Foo 1.0 Foo.qml` to `services/qmldir` (lowercase `singleton`).
3. Anywhere: `import "../services"` then read `Foo.someProperty`.

### Add a native sensor (C++ plugin)

1. Create `native_foo.{h,cpp}` under `plugin/`. Inherit from `NativeSensor`
   and override `poll()`. Use `Q_OBJECT`, `QML_ELEMENT`, and `Q_PROPERTY`
   for exposed values (READ + NOTIFY; add WRITE only for configurable inputs).
2. List both files in `plugin/CMakeLists.txt` under
   `qt_add_qml_module(... SOURCES)`. The flake fileset already takes the
   whole `plugin/` dir, so no flake edit is needed.
3. `nix build .#native-sensors` to compile; sanity-check with
   `nm -DC result/lib/qt-6/qml/NativeSensors/libquickshell-native-sensors.so`
   (your symbols should be `T`, not `U`).
4. In a service: `import NativeSensors`, hold an instance in a typed property
   (`property NativeFoo _foo: NativeFoo {}` — `QtObject` has no default property),
   and bind to `_foo.someValue`.
5. `nh os switch` so the rebuilt module lands on the quickshell systemd
   service's `QML_IMPORT_PATH` (the running bar won't see it before that).

## Conventions

- **Colors and fonts** go through `Theme.color.*` / `Theme.font.*` / `Theme.anim.*` tokens — never hardcode a hex.
- **Pipewire bindings are lazy** — wrap any node you read from with a
  `PwObjectTracker { objects: [thatNode] }` or its values come back undefined.
- **Mutating an array in place does not retrigger bindings** — always reassign
  the whole array (`root.list = newArr`, not `root.list.push(...)`).
  Use `History.push(arr, val, maxLen)` from `services/History.js` for
  rolling-window arrays (returns a new array).
- **`states` is reserved on `Item`** — don't name a property `states`.
- **Repeater delegates** should declare `required property T modelData` and
  `required property int index` — typed errors beat silent undefined.

## Gotchas worth knowing

- Hot-reload watches QML files but **not** `qmldir` — after editing a `qmldir`
  you usually need to touch a QML file or restart Quickshell.
- `services/ColorTokens.qml` on disk is regenerated by matugen on every
  wallpaper change. The source of truth is `matugen/templates/ColorTokens.qml`.
  Don't commit the regenerated output (it's gitignored). `services/Theme.qml`
  is the static aggregator that exposes `Theme.color.*` (forwarded from
  ColorTokens) plus `Theme.font.*` and `Theme.anim.*`. The singleton was named
  `ColorTokens` instead of `Palette` to avoid clashing with `QtQuick/Palette`.
- Two MouseAreas on top of each other: the one declared *later* wins event
  capture. Use `HoverHandler` if you need hover detection that coexists with
  multiple click zones.
- **TextInput on layer-shell needs keyboard focus** — set
  `WlrLayershell.keyboardFocus: WlrKeyboardFocus.OnDemand` on the PanelWindow
  hosting the input. Without it, key events render but Enter/keys are never
  received (needed by `WifiPopup` password field).
- **SystemTray duplicates** — bar modules already showing Bluetooth or
  Network should suppress the corresponding SNI tray items via
  `excludedPatterns` (matches on id/title, case-insensitive). Patterns like
  `"blueman"`, `"network"`, `"nm-"` prevent double icons.
- **Hyprland workspace lists are reactive via ScriptModel** — binding
  `Hyprland.workspaces.values` directly in a Repeater model won't track
  changes. `Tags.qml` wraps it in `ScriptModel { values: … }` so the
  Repeater rebuilds when workspaces change.
